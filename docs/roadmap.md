# Разработка TELO365

Обновлено 21 сентября 2026. Реализована первая рабочая версия всех шести разделов; ниже отделены готовые функции от следующей очереди.

| Этап | Реализовано |
| --- | --- |
| 1. Аккаунт и профиль | Серверное API и SQLite, регистрация, вход/выход, защищённые сессии, цель, целевой вес, часовой пояс, пароль и одноразовый резервный код, экспорт и удаление аккаунта. Почту можно подтвердить и использовать для сброса в закрытом тестовом ящике. |
| 2. Вес и привычки | Записи по датам с исправлением и удалением, график настоящей истории, свои привычки, дневные отметки, обновление между устройствами после входа. Новый пользователь получает пустую историю. |
| 3. Питание | Продукты на 100 г, рецепты из ингредиентов, собственный каталог, порции, план и дневник съеденного, суммы калорий/БЖУ. В дневнике сохраняется снимок блюда. |
| 4. Тренировки | Упражнения и программы, журнал подходов/повторов/секунд/рабочего веса, продолжение занятия, завершение и история. |
| 5. Покупки | Генерация из плана на период до 31 дня, суммирование ингредиентов в граммах, ручные позиции, сохранение отметок при неизменном количестве, синхронизация. |
| 6. Основа открытого сервиса | Гостевая главная, отдельное демо, редактор контента с ролью администратора, HTTPS, systemd, ежедневные копии с проверкой целостности, команды восстановления, локальная проверка доступности каждую минуту. |

## Проверки версии

Сборка TypeScript/Vite, 12 серверных и 12 браузерных проверок desktop/mobile. Проверены права доступа, восстановление аккаунта, серверное хранение после перезапуска, резервное копирование и восстановление в отдельный файл. HTTPS-версия дополнительно проверяется на установленной ВМ. Детали эксплуатации — [в инструкции](../deploy/application.md).

## Следующая очередь

1. Провести пользовательскую проверку: регистрация → цель → вес и привычки → питание → тренировка → покупки. Собрать замечания к мобильной версии и навигации.
2. Наполнить общий каталог проверенными продуктами, рецептами и программами. Сейчас предустановленные записи явно помечены как учебные примеры; личные продукты можно вводить с этикеток.
3. Выбрать SMTP-провайдера для внешней доставки, настроить SPF/DKIM/DMARC и заменить тестовый Mailpit. Сценарии подтверждения адреса и восстановления по ссылке уже реализованы; сейчас письма не уходят во внешнюю почту.
4. Подключить выбранное внешнее хранилище копий, проверить восстановление после потери ВМ. Сейчас автоматические копии хранятся на самой ВМ 14 дней.
5. Подключить внешний мониторинг HTTPS и доставки уведомлений владельцу. Текущий timer обнаруживает локальные ошибки и пишет в журнал, но не сообщает о потере интернета или хоста.
6. Заполнить сведения о владельце сервиса и окончательные условия обработки данных, назначить администратором зарегистрированный аккаунт владельца. Права не выдаются автоматически первому посетителю.

Пункты 3–6 требуют выбранных внешних сервисов или данных владельца. Платежи/PRO, фотографии прогресса, интеграции с трекерами и магазинами — отдельные будущие функции, в эту версию не входят.

## Техническая основа

React/TypeScript на клиенте, Node.js ES modules на сервере, SQLite WAL со схемой версии 1. Каждая личная запись принадлежит пользователю; сервер проверяет доступ. Изменяющие запросы защищены проверкой Origin и заголовка, сессии — HttpOnly/Secure cookie. Продукт работает на отдельной ВМ TELO365 через существующий входной nginx SoulCam.

При росте нагрузки сначала измерять время запросов, размер базы и потребление памяти; переход к PostgreSQL или очередям делать по выявленной необходимости. Любое изменение схемы сопровождать миграцией, резервной копией и проверкой восстановления.
