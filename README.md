# TELO365

Сервис питания, движения и привычек: **https://telo365.ru**. Первая рабочая версия с аккаунтами и серверным хранением данных. React 19 / TypeScript / Vite, Node.js 24 / SQLite, адаптивный интерфейс на русском.

## Возможности

- Регистрация, вход, профиль, цель, часовой пояс. Восстановление доступа по одноразовому резервному коду; экспорт данных и удаление аккаунта.
- Вес по датам, история и график, свои привычки и ежедневные отметки. Данные доступны на разных устройствах после входа; обновление каждые 20 секунд и при возвращении на вкладку.
- Продукты, рецепты, собственный каталог, порции, план питания и дневник съеденного с подсчётом калорий и БЖУ. Изменения каталога не переписывают старый дневник.
- Программы тренировок, подходы, повторы / секунды, рабочий вес, продолжение и история занятий.
- Покупки из плана питания за выбранный период: объединение ингредиентов, ручные позиции, отметки купленного.
- Публичная главная, редактор общего каталога и описания сайта для администратора, ежедневные резервные копии и локальная проверка доступности.

Новый аккаунт начинает с пустой личной истории. Начальные продукты и программы помечены как учебные примеры. Старое интерактивное демо доступно отдельно на `/demo`; его данные хранятся только в браузере.

## Локальный запуск

Требуется Node.js **24.14+**; на ВМ установлен 24.21.0. В PowerShell:

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run server
```

Во втором терминале:

```powershell
npm.cmd run dev
```

Открыть http://127.0.0.1:5173. Vite проксирует `/api` на сервер 127.0.0.1:1435. База создаётся в `data/telo365.sqlite` и исключена из Git. На Linux использовать `npm` вместо `npm.cmd`.

## Проверки

```powershell
npx.cmd playwright install chromium
npm.cmd run build
npm.cmd run test:server
npm.cmd run test:e2e
```

12 серверных и 12 браузерных проверок: изоляция аккаунтов, защита запросов, восстановление доступа, порции, покупки, подходы, копирование базы, сохранность после перезапуска; сквозной сценарий desktop/mobile и демо. Браузерные тесты используют отдельную базу `artifacts/e2e.sqlite`; локальные серверы с уже занятыми тестовыми портами должны использовать тестовые данные. В CI серверы запускаются заново.

## Устройство проекта

- `src/App.tsx` — гостевые страницы и вход; `src/components` — кабинет и разделы; `src/api.ts` — клиент API.
- `server` — HTTP API, SQLite, аккаунты, дневники, каталог и административные команды. Сервер написан на JavaScript ES modules.
- `deploy` — systemd, установка, резервное копирование, восстановление, nginx.
- `tests` — браузерные сценарии; `server/app.test.mjs` — интеграционные проверки API.
